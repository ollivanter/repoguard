    What happens when you press run.

    1. 01

      Metadata, then a shallow clone

      One call to the GitHub API checks the repo exists, its size and visibility. Then a git clone --depth into a temp folder with symlinks, hooks and LFS disabled. It's deleted when the scan ends.

    2. 02

      Secrets, now and in history

      Every tracked file and every line added in the replayed commits is matched against token formats. A key deleted last year still counts: it's in every clone.

    3. 03

      Dependencies, by path

      Lockfiles are walked like the package manager would, so a vulnerable package shows the chain that pulled it in. Exact versions are batch-checked against OSV.dev.

    4. 04

      Workflows and containers

      Actions are checked for script injection, unpinned tags and privileged PR checkouts. Dockerfiles for root users, baked-in secrets and unverified downloads.

    Tokens are sent only to GitHub, held in memory for one scan and never written to disk or logs.

    The token RepoGuard needs

    1. Open GitHub → Settings → Developer settings → Fine-grained tokens and generate a new token.
    2. Repository access: Only select repositories, then pick the repo you want to scan.
    3. Permissions: Contents → Read-only. Metadata (read-only) is added automatically. Nothing else.
    4. Set a short expiry (7 days is plenty) and paste the github_pat_… token here.

    For an organization that uses SSO, authorize the token for it after creating it. Public repos don't need a token; it only raises the rate limit.
